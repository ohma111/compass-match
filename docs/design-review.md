# v3 デザインレビュー記録

撮影: `npm run dev` → `npm run preview:shots` (`scripts/screenshots.mjs`)。
`/dev/preview/*` (開発時だけ存在するフィクスチャ画面) を Playwright の Chromium で 375×812 と 1440×900 で撮影した。
最終版は `docs/screenshots/`。375px は全体 (`*-375.png`) と最初に見える範囲 (`*-375-fold.png`) の2枚。
全体の画像では、固定のヘッダー・タブバーがページの途中に写る (撮影方法の都合で、実機ではそうならない)。

採点は Awwwards の4軸で各10点。比べる相手は v2 ではなく、実際の受賞作 (ゲーム・エンタメ系の SOTD)。

## デザインの計画 (frontend-design の手順)

- **題材**: #コンパスの 3対3。試合前のチーム編成画面にある、斜めに並んだ3つの枠と、空き枠が埋まっていく緊張感。
- **主な役割**: 「今から一緒に遊べる人」を一目で見つけて、3タップ以内で参加・募集すること。
- **色** (5色 + 目的色): 床 `#E6E8EE` / シート `#FFFFFF` / インク `#16161D` / 味方(コバルト) `#2340F0` / シグナル(朱) `#D0341B`。目的色は白地で AA を満たす濃さ (ランク `#1B3FD8`、エンジョイ `#0B8457`、大会練習 `#C2410C`、カスタム `#7C3AED`)。
- **書体**: 見出し・数字・席の頭文字は Dela Gothic One (1ウェイトの極太)。本文は Zen Kaku Gothic New。
- **レイアウト**: スマホは1列、上にインクのヘッダー、下にタブバー。PC は左に固定の操作欄、右に内容 (一覧は2列、詳細は「席」と「メンバー専用」の2列)。左揃え。
- **軸になる形**: 12度傾けた平行四辺形の「席」(`Lineup`)。一覧(小)・詳細(大)・募集作成と登録のプレビューで同じ形を使う。空き席は斜線、自分の席は朱の枠。
- **動き**: 参加が確定した瞬間だけ (自分の席が滑り込み、「参加確定」/「満員」の判が押される)。`prefers-reduced-motion` では動かない。

### 計画の見直し (汎用の既定値になっていないか)

| 最初の案 | 気づいたこと | 変えたこと |
| --- | --- | --- |
| v2 と同じ暗い背景 + 蛍光色 | 「黒背景 + 1色の蛍光」はよくある既定値。夜に使う前提でも暗くする必然はない | 明るい床とインク。暗さはヘッダーと「部屋番号」など要所だけに使う |
| 角丸カードを並べる | SaaS のカードキットそのもの | 角丸をやめ、カードゲームのカードのように右上だけを斜めに切る。主ボタンも右下を切る |
| 英字の小見出し (MY RECRUITMENTS など) | 字間を広げた大文字ラベルは典型的な飾り | 日本語の見出しを Dela Gothic One で。ラベルを足さない |
| 残り枠を ●●○ で表示 | 情報は伝わるが、世界観がない | 試合前の編成画面の「席」にする。誰が入っているかも頭文字で分かる |
| 各セクションのフェードイン | 1か所に集中させるという要件に反する | 参加確定の瞬間だけ動かす |

## 各周の指摘 (厳しめ)

### 1周目
- 開発用の「N」バッジが左下に重なる (撮影の邪魔、実機では出ないが確認しにくい)。
- 参加確定の判 (満員) が真ん中の席の名前を隠す。動きが終わっても隠したまま。
- 一覧の小さな席で、名前が見えない参加者を「・」で表していて、何の記号か分からない。
- 押せない主ボタンが薄い青で、押せそうに見える。
- 一覧のカードがすべて同じ見た目で、目的の違いが小さな札にしか出ていない。
- 詳細 (375px) で大きな席が画面の端で切れる。
- 引き継ぎコードが「9W / HB」の途中で折り返し、写し間違いを誘う。
- 良い点: 「あと8分」を Dela で大きく見せる時刻、インクの部屋番号、斜めの席は題材に合っていて覚えやすい。

### 2周目
- **不具合**: 詳細を開くとチャットの `scrollIntoView` がページ全体を最下部へ動かし、部屋番号より先にチャットが出る。
- スマホの募集ボタンの帯で、タイトルと要約が二重に出ている。
- 判が右上で「3人中3人」の文字に重なる。
- 一覧に強弱がなく、どれから見ればいいか分からない (受賞作は情報の階層がはっきりしている)。

### 3周目
- 先頭の「まもなく始まる」募集を2列分の大きさにし、大きな席を見せた → 一覧に階層ができた。
- PC 左の絞り込みが白い箱の縦積みで、フォームの部品に見える。
- スマホの登録画面に、この画面ならではの要素がない (入力欄だけ)。

### 4周目
- 判がまだ自分の席の文字 (ランク) に重なる。席が細いとランクが「S4〜 / S6」と折り返す。
- 大きな席の匿名の参加者に大きな「・」が出ていて、意味がない。

### 5周目
- PC の引き継ぎコードが「9WHB- / 2NCE」で折り返す。
- 空の状態の見出しが 375px で「ん」だけ次の行に落ちる。
- 募集作成 (PC) のプレビューの席が小さく、頭文字が読めない。

### 6周目 (最終)
- 細い席で「募集者」「あなた」が縦書きのように崩れていた → 自分が募集者のときは王冠のアイコンだけにした。
- 残る弱点 (8点台にとどまる理由):
  - PC の詳細・マイページは右側の余白が多い。情報量に対して画面が広い。
  - ログイン画面は機能的だが、題材らしさは見出しの書体だけ。
  - 一覧の主ボタンが続くため、スマホでは青の面積が大きい。

## 品質の最低ラインの確認
- 375px / 1440px: 全画面で横スクロールなし (撮影スクリプトが `scrollWidth` を確認)。
- タップ領域: ボタン・チップ・リンクは 44px 以上 (`min-h-11`/`min-h-12`)。チャットの「通報」も 44px に広げた。
- コントラスト: 本文 `#16161D`/白 18:1、補足 `#5A5F70`/床 5.2:1、白/コバルト 6.9:1、白/朱 5.0:1、朱の文字は床の上では `#B52D16` (5.1:1)。
- キーボード: すべての操作要素に 3px のインクの `:focus-visible`。選択チップは内側の radio/checkbox にフォーカスが来ると枠が出る。「本文へ移動」リンクあり。
- 動き: 参加確定の1か所だけ。`prefers-reduced-motion: reduce` ではすべて止まる。
- 速度: 画像なし。演出は CSS だけ。フォントは next/font で自己ホスト・`display: swap`。

### 審査員の指摘への対応 (7周目)
1. 募集作成ではタブバーを出さず、画面下は「席のプレビュー + 募集する」の64pxのバー1本 (safe-area 分の余白込み)。参加方式まで最初の画面に入る。
2. Dela Gothic One は22px以上だけ。ロゴ (スマホ)、小見出し、小さい席の頭文字、「あと◯人/満員」は Zen Kaku Gothic New 900 + 字間 0.02em。
3. 参加後の詳細は、カウントダウンのすぐ下に部屋番号とコピー。
4. ホームの先頭カードはスマホでは小さい席。大きな席は PC (xl) だけ。
5. 自動タイトルから人数を外した (「ランク S4〜の募集」)。判は席の上ではなく「パーティ」見出しの右に押す。
6. タブバー中央の「募集する」を浮かせずバーに収め、切り欠きを他のボタンと同じ10pxに。ヘッダーはプロフィールの有無ではなくログイン状態で出し分け。
7. 登録はユーザーID → パスワード → ランク帯 → 表示名の順。押せないボタンに「はじめる (あと◯項目)」。登録・ログイン画面ではタブバーを出さない。
8. 補足文字の色を #565B6B (床の上で 5.5:1) に、11px以下の文字を12pxに。空き席の「空き」は白地に濃い文字。入力欄の例文も同じ色。
9. 絞り込みチップの右端をフェードさせ、続きがあることを示す。カードのタグは1つ + 「+N」、1行に固定。
10. ページ全体を縦の flex にして、短いページでもフッターが画面の下に付く (余白の固定値をやめた)。「30分以内」は role="switch" と aria-checked を持つ 44×24 のスイッチ。

### ロビー (審査員の提案を実装)
- 募集詳細で、最初の空き席そのものが「参加する/申請する」ボタン (button 要素、キーボードで押せる)。文字のボタンも下に残す。
- 開いている間は15秒ごとに状態を取り直し (画面が見えているときだけ)、誰かが入るとその席が斜めに滑り込んで一瞬光る。自分の参加確定でも同じ動き + 判。`prefers-reduced-motion` では止まる。
- 詳細の大きなカウントダウンは60分を切ると「あと7:42」のように1秒ごとに刻む。

### 審査員2の指摘への対応 (10周目)
1. 登録はユーザーID・パスワード・同意だけ。表示名はユーザーIDで始まる。ランク帯は、初めて「参加する」「募集する」を押したときに、その場で1タップで選ぶ (おすすめの S1〜S3 を最初から選んだ状態で表示)。選ぶと、そのまま参加・募集を続ける。一覧のカードから押した場合は、詳細ページで聞いてから参加する。引き継ぎコードの画面は残した。DB では `profiles.rank_confirmed` と `confirm_my_rank()` を追加 (未適用の v3 マイグレーションに含めた)。
2. 埋まった席の色はどこでもコバルト。黒は募集者だけ (一覧で名前が見えない参加者も、以前の濃い灰色をやめてコバルトにした)。
3. 大会練習の色を、朱に近いオレンジ `#C2410C` から黄土色 `#8A6100` (白地で 5.5:1) に変更。「あと8分」「開催中」の朱とは明度も色相も離れた。
4. 引き継ぎコードは4文字ずつ区切って並べる (スマホは2×2、広い画面は1行)。途中で改行しない。
5. 「満員」「参加確定」の判は席の並びの上 (見出しの右) に置き、席との間を空けた。埋まった席の文字 (ランク・アイコン) は白90%。
6. 「くわしく決める」の行が空白に見えていたのは、全体の画像で固定バーが重なっていたため。下に固定バーと同じ高さの余白を足し、撮影でも固定バーを外して内容を確認した。
7. PC の募集ボタンは高さ64px以上 (2行の要約が窮屈にならない)。
8. マイページのカードのボタンは「管理する」。補足・フッターの灰色は #565B6B (#5A5F6B より濃い、床の上で 5.5:1)。

### 文言の方針と例
- UI を見れば分かることは書かない (例: 「タップで選んで『募集する』を押すだけ」を削除。募集作成の説明は「終わりは開始の1時間後です。」だけ)。
- #コンパスの遊び方に寄せる: 「空いてる席に入れば、そのまま3人で回せます。部屋番号は入った人にだけ出ます。」「部屋を立てたら部屋番号を入れておくと、入った人がすぐ来られます。」「まだ部屋番号がありません。募集者が部屋を立てたら、ここに出ます。」
- 空の状態は次の一手を示す: 「まだ誰も募集していません / 先に出しておけば、来た人がそのまま入ってきます。」「まだ誰も話していません。『よろしく!』からどうぞ。」
- エラーは「何が起きたか + 次にすること」: 「うまくいきませんでした。少し待ってから、もう一度押してください」「募集を読み込めませんでした。少し待ってから、ページを読み込み直してください。」
